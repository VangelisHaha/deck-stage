# 新增与修改的工作规范

新建一份稿子、给稿子加页或改文案时的流程。目标：改得准、不漏同步、不泄露、不把时间花在逐页截图上。

## 新建

1. `scripts/new_deck.sh "标题"` 生成稿子（`index.html` + `notes.js` + `assets/`），**默认建在 `~/Documents/DeckStage/<标题>/`**——这是 DeckStage 的默认稿库，启动时自动登记，建在这里稿子会直接出现在 DeckStage 里，**不用问用户放哪、也不用登记目录**。用户明确指定了别的位置，才用 `new_deck.sh <目标目录> "标题"`。
2. 先定内容再定样式：写清受众、主线、每一段要讲几分钟，把结论写进稿子目录的 `AGENTS.md`（自己新建，写法见文末）。
3. 改 `index.html` 的 `<style>` 定风格；每页一个 `<section class="slide" data-t="…">`；每页在 `notes.js` 里配同名台词。
4. 页数多、一份稿子里有很多页内容时，参考 `references/split-deck.md` 拆分。
5. 需要动效参考 `references/effects.md`；页面要调本机接口参考 `references/deckstage.md`。
6. 体检，通过后告诉用户重点看哪几页。

## 修改

| 改什么 | 做法 |
|---|---|
| 文案、结构、删页、加页 | **先给方案，等用户确认再动手**。方案里写清改哪几页、台词怎么跟着改 |
| 配色、错别字、补导出降级规则 | 直接改 |
| 页面文案 | **同步改 `notes.js` 对应台词**。页面上的字和台词是同一句话的两份拷贝，体检只能查 key 对不对，查不了内容一致 |
| 增删页 | 复查跨页引用（「前面那 13 个任务」「刚才那张表」）和总数（「六个工具」）；页码、圆点、台阶条是动态算的，不用管 |
| 新增渐变文字 | 登记到 `deck.config.js` 的 `gradientText`，否则导出的 PPTX 里那行字是空白 |

改完：

1. 跑体检（`check_deck.py`，单文件稿和拆分稿都用它），0 error 才算完。
2. **不逐页截图验证。** 截图又慢又容易把服务搞崩。告诉用户改了哪几页、重点看什么，让他自己看。
3. **引导用户去 DeckStage 看**：跑 `scripts/open_in_deckstage.sh <稿子目录>`（它会做 URL 编码并 `open "deckstage://open?path=…"`，在稿库里选中这份稿子，不会自动开始放映；稿子不在已登记的稿库里时 DeckStage 会自动登记它所在的目录）。然后告诉用户：「已在 DeckStage 里选中《标题》，右侧浮窗能先看目录和缩略图，回车开始放映」。没装 DeckStage 的机器脚本只打印提示，告诉用户稿子要用 DeckStage 放映（或在装了 DeckStage 的电脑上用「添加远端目录」）。

## 数据口径

稿子里出现的数字，被听众追问时要能说出来源。在 `AGENTS.md` 的「数据口径」表里登记：页面上的数 → 来源（文档、日志、代码位置）。编出来的演示内容（对话、示意图）页面上标「演示」。

## 分享前脱敏

导出 ZIP / PPTX 或把稿子发给别人之前，检查**页面、台词、素材、后台服务脚本**里有没有：

- 客户姓名、账号、金额、流水号、同事姓名
- 群 id、webhook、数据库地址、内网地址、密钥、令牌
- 写死了这些值的脚本（后台服务脚本常见）。打包前把配置抽到不随稿子分发的文件里

## 协作约定文件 AGENTS.md

每份稿子目录放一个 `AGENTS.md`，写给接手的 AI：内容来源、受众、文件结构、放映与体检命令、改动流程、数据口径、脱敏要求。风格约定（平视不俯视、禁用词、长度上限）也写在这里，**不要写进 skill**——不同场合的稿子风格不该互相绑死。
